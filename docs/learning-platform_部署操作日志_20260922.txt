十、遇到的问题与处置
======================================================================

问题 1：跳过「停止后端」直接替换了 JAR

现象：
  在未执行第 8 节步骤 1 的情况下，先完成了后端 JAR 与前端 dist 的替换。
  旧进程（PID 476601）仍在运行，使用的仍是旧代码。

风险：
  Linux 下 JVM 运行期间会按需从 JAR 读取资源（例如加载 Notebook 模板）。
  运行中的 JAR 文件被覆盖后 inode 发生变化，可能导致运行时读取异常。

处置：
  确认进程仍在运行后立即执行 kill 停止，再重新启动新版本。
  最终服务运行正常，未观察到副作用。

建议：
  后续部署严格遵循「先停后端 → 再替换文件 → 最后启动」的顺序，
  不要在旧进程仍运行时覆盖 JAR。

问题 2：多行命令粘贴导致密码提示被吞

现象：
  多条带 -p 参数的 mysql 命令一次性粘贴时，出现
  ERROR 1045 (28000): Access denied for user 'root'@'localhost' (using password: NO)。

原因：
  终端的密码交互提示出现在多行粘贴内容的中间，
  导致后续内容与密码输入互相干扰，MySQL 收到空密码。

处置：
  单独复制执行每一条需要密码的命令，问题即消失。

建议：
  需要输入密码的命令一律单独一行粘贴，不要与其他命令合并。

问题 3：kill 后进程未立即退出

现象：
  执行 kill 476601 后等待 6 秒，进程仍存在，但端口已释放。

原因：
  Spring Boot 优雅关闭需要等待现有请求完成，存在活跃连接时会较慢。

处置：
  继续等待约 18 秒后进程自行退出。
  若长时间不退出，可使用 kill -9 强制结束。

问题 4：mvn package 产物名与线上运行名不一致

现象：
  Maven 默认产物为 LabCore-0.0.1-SNAPSHOT.jar，而线上运行的文件名为 labcore.jar。

处置：
  在部署包中将其重命名为 app.jar，部署时再复制为 labcore.jar。
  该命名方式沿用既有部署文档约定，目的是区分待部署产物与线上版本，
  同时保证启动脚本与进程检测命令（按 labcore.jar 匹配）继续有效。

关于数据库回滚：
  contributor 是本次新增的表，多出来的表不会影响旧版本代码运行
  （旧代码不访问该表）。因此一般情况下无需回滚数据库。
  只有在确认必须回退数据库结构时，才执行：

  /opt/learning-platform/mysql/bin/mysql -uroot -p -h127.0.0.1 -P3306 labcore < "$BACKUP_DIR/labcore.sql"

  数据库回滚会覆盖部署之后产生的所有新业务数据，执行前必须确认。
